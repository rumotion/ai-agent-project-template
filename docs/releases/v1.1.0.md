# v1.1.0 - Confirmed quota pacing and portable workflows

A clearer starting point for AI coding projects: shared instructions, durable
project memory, verified workflows and optional quota pacing. This release adds
new capabilities while keeping the template's Python standard-library baseline.

![AI Agent Project Template v1.1.0: foundation and new capabilities](https://github.com/rumotion/ai-agent-project-template/releases/download/v1.1.0/template-overview-v1.1.0.png)

## New in this release

### Optional, confirmed quota pacing

Prepare a bounded plan for useful queued work, review its provider, target,
deadline, worker count and completion reserve, then obtain separate human
confirmation before activation. The local CLI stores sanitized numeric readings
in private SQLite state outside projects and advises worker concurrency.

- Default OFF; handoffs do not automatically resume it.
- Documented Claude statusline input and manual Codex/Google readings.
- Handles stale data, short-window constraints, quota resets and wrap-up time.
- No credentials, network requests, agent launching or automatic paid overage.

[Commands, data formats and implementation](https://github.com/rumotion/ai-agent-project-template/blob/v1.1.0/docs/usage-pacing.md).

### Portable workflow skill discovery

Ten thin skill entry points link to the canonical workflows, preserving current
Antigravity discovery after its workflow-to-skills migration. Claude and Cline
use generated mirrors. The template now includes **22 skills and workflow entry
points** while keeping procedures in one canonical location.

### Cleaner project starters and upgrades

- Observable success checks first; short routine plans and phases for complex work.
- English repository documentation and commit messages across clients.
- Corrected generated README and Memory Bank text encoding.
- Upgrades stop before writing when new skill names conflict with custom content.
- Refreshed model-routing, goals, hooks and current-client compatibility guidance.

## What the template includes

Canonical `AGENTS.md`, indexed Memory Bank and handoffs, typed context compiler,
scoped task/result contracts, ten canonical agent workflows, advisory hooks and
a local push backstop, project creation/upgrades, mirror generation and
dependency-free validation. Existing project copies do not activate pacing
when upgraded.

## Upgrade

Use a separate checkout of this release to preview the target changes:

```bash
python scripts/upgrade-target.py --target ../existing-project --dry-run
```

Review conflicts and project-specific rules before applying. Keep company
information and private runtime state in their own repositories.

## Verification and limits

The full local gate covers 165 required files, 10 instruction adapters, 17
context budgets, schema/contract/context checks, hooks and generated mirrors.
Eighteen pacing/integration regressions use temporary databases and simulated
clocks. Fresh project output was checked for readable English documentation.
GitHub Actions runs Windows/Linux with Python 3.9 and current Python.

Pacing is an adviser, not a spending controller or dispatcher. Synthetic hook
fixtures do not certify live-client enforcement. Native client integration and
provider cache/quota behavior require their own smoke tests. Local mail remains
an optional design assessment; no mailbox system or Ponytail plugin is installed.
